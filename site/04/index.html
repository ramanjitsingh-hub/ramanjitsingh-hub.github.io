Investigation 04 · Model routing

When is a cheap model good enough?

Luna, the assistant I am building, sends each request to the cheapest model that can handle it. This investigation measures what that rule is worth. On 44,241 prompts answered by 13 language models, a router that reads only the prompt matches GPT-4o at about a tenth of its cost. Most of that gain comes from recognising the kind of task, and on a kind of task it has never seen, the same router does worse than a fixed model. A certified version keeps its promise, and the page measures what the promise costs.

§1The question

Language models differ in price by a factor of more than a hundred. In this data the cheapest costs 6 cents per thousand prompts and the most expensive $7.66. They differ far less in quality.

Luna answers each request with the cheapest model that can do the job well. Writing that rule down raises three questions. What is the best possible rule, if we knew how each model would do on each prompt? How much of it can be learned from the text of the prompt alone? And can a level of quality be promised before the next thousand requests arrive?

This page answers each one on the same data. Luna's own traffic is private, so the experiments use a public benchmark in which every prompt was sent to all 13 models. That design is what makes the questions answerable, since for every prompt we know what each model would have done. Section 10 says what carries back.

§2Routing as a decision

A prompt \(X\) arrives. Model \(k\) would answer it with score \(Y_k \in [0,1]\) at cost \(c_k\). Write \(\mu_k(x) = \mathbb E[Y_k \mid X = x]\) and \(\kappa_k(x) = \mathbb E[c_k \mid X = x]\). A router \(\pi\) maps a prompt to a probability distribution over models, so random choices are allowed. Its value and cost are

$$V(\pi) = \mathbb E \sum_k \pi_k(X)\, Y_k, \qquad Q(\pi) = \mathbb E \sum_k \pi_k(X)\, c_k ,$$

and the aim is the highest value for a given budget \(B\).

Proposition 1 · the rule and the frontier

For a price of quality \(\lambda \ge 0\) let \(\pi_\lambda(x) = \arg\max_k\, \mu_k(x) - \lambda\, \kappa_k(x)\). Then \(\pi_\lambda\) maximises \(V - \lambda Q\) over all routers, and solves the budgeted problem whenever \(Q(\pi_\lambda) = B\). The best value at each budget, \(F(B)\), is concave and nondecreasing, and its graph is the upper concave hull of the points \((Q(\pi_\lambda), V(\pi_\lambda))\).

proofBy the tower rule \(V - \lambda Q = \mathbb E \sum_k \pi_k(X)\,(\mu_k(X) - \lambda \kappa_k(X))\), which is maximised prompt by prompt by putting all weight on the argmax. If \(Q(\pi) \le B = Q(\pi_\lambda)\), then \(V(\pi) \le V(\pi_\lambda) - \lambda\,(Q(\pi_\lambda) - Q(\pi)) \le V(\pi_\lambda)\). Routers can be mixed and \(V, Q\) are linear in \(\pi\), so the set of reachable \((Q, V)\) is convex. Its upper boundary is therefore concave, and each supporting line has slope \(\lambda\) and touches it at \(\pi_\lambda\). ∎

One consequence decides how routers should be judged. A router that learns nothing about the prompt has constant estimates, so it can only choose a single model. By mixing two models at random it can still reach any point on the hull of the single models. A claim that a router "matches model A at a fraction of the cost" shows skill only if it beats that hull, and every comparison below is made against it.

Proposition 2 · the cost of wrong estimates

If \(\hat\pi\) uses estimates \(\hat\mu, \hat\kappa\) in place of \(\mu, \kappa\), then

$$(V - \lambda Q)(\pi_\lambda) - (V - \lambda Q)(\hat\pi) \;\le\; 2\, \mathbb E \max_k \Big( |\hat\mu_k(X) - \mu_k(X)| + \lambda\, |\hat\kappa_k(X) - \kappa_k(X)| \Big).$$

proofWrite \(u = \mu - \lambda\kappa\), with \(\hat u\) defined the same way, and let \(k^\ast, \hat k\) be the two choices at a prompt. Then \(u(k^\ast) - u(\hat k) = [u(k^\ast) - \hat u(k^\ast)] + [\hat u(k^\ast) - \hat u(\hat k)] + [\hat u(\hat k) - u(\hat k)]\). The middle term is at most zero by the choice of \(\hat k\), and each outer term is at most \(\max_k |u_k - \hat u_k|\). ∎

A router therefore needs good score estimates only where they change the decision. The bound cannot be checked on data, because \(\mu\) is never observed. Each prompt has one answer per model, a single draw of \(Y_k\).

Proposition 3 · the oracle overstates what is reachable

For every router, \(V(\pi) \le \mathbb E \max_k \mu_k(X) \le \mathbb E \max_k Y_k\).

proof\(V(\pi) = \mathbb E \sum_k \pi_k \mu_k \le \mathbb E \max_k \mu_k\). The second inequality is Jensen's, since the maximum is convex, so \(\max_k \mathbb E[Y_k \mid x] \le \mathbb E[\max_k Y_k \mid x]\). ∎

The right-hand side is the hindsight oracle that routing papers often report as a ceiling. It is credited whenever any of the 13 answers happens to be right, and the gap between the two sides is luck. Section 8 measures it.

§3Thirteen models, one price list

SPROUT holds prompts from six benchmarks, from competition mathematics to questions over retrieved documents, each answered by all 13 models. Each answer is scored against a reference answer by a judge model, Llama 3.1 70B. Half the scores are exactly 1, a quarter exactly 0, and the rest partial credit. Costs use each answer's token counts and the per-token list prices published with the data[1].

§4Who beats whom

Routing can only help where a cheaper model is right and a dearer one is wrong. If difficulty were one number per prompt and ability one number per model, that would never happen. The matrix of right and wrong answers would form a staircase, the pattern Guttman described for test questions in 1944[7], and routing would reduce to judging how hard a prompt is.

§5Learning to route

Four routers are compared, all trained on the 30,968 training prompts and tuned on the 6,636 validation prompts. Each estimates the 13 expected scores and costs for a new prompt and applies the rule of Proposition 1. Sweeping \(\lambda\) traces its frontier.

Benchmark label. Knows which benchmark the prompt came from and predicts each model's average score there. A deployed router has no such label, so this is a reference point. Text, ridge. TF-IDF features of words and character fragments, 120,004 in all, with one ridge regression to all 13 scores. Text, boosted trees. Gradient-boosted trees on a 256-dimensional SVD of the same features. Ensemble. The average of the two text routers. §7A kind of task never seen

A product's traffic changes. New users bring new kinds of request, and a router trained last month meets tasks it was never shown. To imitate this, the text router is retrained six times, each time without one benchmark, and tested on the benchmark it never saw. It is compared with two alternatives. One is a fixed ranking of models learned from the other benchmarks, which also has never seen the new task. The other is the hull of fixed models on the new benchmark itself, which needs labelled examples of it.

§9A guarantee, and its price

Section 5 ended with a router that matched GPT-4o on validation and then fell short on test. That is the normal result of picking a threshold on one sample. The point chosen is the cheapest that looked good enough, and among many candidates the one that looked best was often lucky.

The remedy treats each \(\lambda\) as a hypothesis. Order them from expensive to cheap and test \(H_j\colon V(\pi_{\lambda_j}) < \text{target}\) on \(n\) calibration prompts. Move to the next only while the current one is rejected at level \(\delta\), and stop at the first failure. This fixed-sequence procedure, used in this way by Angelopoulos and coauthors[5], needs no multiplicity correction, and the chosen router falls short of the target with probability at most \(\delta\). If nothing is rejected the router abstains and every prompt goes to GPT-4o.

Each test needs a p-value for a mean of scores bounded in \([0,1]\). Hoeffding's inequality gives one. A sharper one comes from betting[6]. Start with capital 1 and bet a predictable fraction on each score exceeding the target, so

$$K_t = \prod_{i \le t} \big(1 + \eta_i\,(x_i - \text{target})\big), \qquad 0 \le \eta_i \le \tfrac{1}{2\,\text{target}} .$$

If the true mean is at most the target, \(K_t\) is a nonnegative supermartingale, so by Ville's inequality it reaches \(1/\delta\) with probability at most \(\delta\), and \(1/\sup_t K_t\) is a valid p-value. Here the target is GPT-4o's own test score and \(\delta = 0.1\).

To check the guarantee rather than trust it, the 6,637 test prompts serve as the whole population. Calibration samples are drawn from them, so the true score of every \(\lambda\) is known exactly and each violation can be counted. Each setting is repeated 1,000 times.

§10What carries back to Luna

Three lessons carry over. A router should be judged against the hull of fixed models, because a random mix of two models is free to build and already beats every single model in between. Most of the saving comes from knowing the kind of task, so a router belongs on a product's own traffic, and has to be checked again when that traffic changes, since Section 7 shows it can fall below a fixed choice on unfamiliar work. And a promise about quality needs a held-out sample and a valid test. A threshold that looks safe on validation fails about four times in ten.

The next milestone takes up the question that this data hides. In deployment a router sees only the score of the model it chose, never the other twelve. Learning under that partial feedback is a contextual bandit problem, with its own trade-off between trying models and using the best one known. I will also replace the TF-IDF features with sentence embeddings computed on the laptop GPU, to see how much of the within-benchmark gap of Section 6 better features can close.
