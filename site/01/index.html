Investigation 01 · Adaptive Bayesian state estimation, phase one

Re-deriving a production cycle predictor

At FemoraAI I shipped a per-user Kalman filter that predicted the start of each user's next period. This investigation ports that system line by line, derives what it actually computes, and finds four concrete failure modes. It then replaces the system with an exact Bayesian grid filter and measures both against ground truth on 6,000 simulated users.

§1The system as shipped

The predictor sees one number per completed cycle, the number of days between consecutive period starts, clamped to the interval [15, 60].

Two estimators run side by side on that sequence. The first is a scalar Kalman filter on a random-walk level,

$$x_k = x_{k-1} + w_k,\quad w_k\sim\mathcal N(0,q),\qquad z_k = x_k + v_k,\quad v_k\sim\mathcal N(0,r),$$

with \(q = 0.5\), \(r = 4\), and the prior \(x_0 \sim \mathcal N(\text{self-reported length},\,9)\). The second is an exponentially weighted moving average with an exponentially weighted variance,

$$m_k = \alpha z_k + (1-\alpha)\,m_{k-1},\qquad s_k^2 = (1-\alpha)\big(s_{k-1}^2 + \alpha\,(z_k - m_{k-1})^2\big),\qquad \alpha = 0.3 .$$

An observation is discarded as an outlier when \(|z_k - m_{k-1}| > 3\,s_{k-1}\). Otherwise both estimators update and the service reports

$$\mu_k = \tfrac12\hat x_k + \tfrac12 m_k,\qquad \sigma_k^2 = P_k + s_k^2,\qquad \text{interval} = \mu_k \pm 1.2816\,\sigma_k\,c_k ,$$

where \(c_k \in [0.8, 2]\) is a scale that a feedback loop nudges toward an 80% empirical hit rate, and \(\alpha\) is retuned within [0.1, 0.6] by the same loop. A separate layer shifts \(\mu\) by learned per-symptom offsets. Symptoms are out of scope here.

The port in femora_port.py mirrors the Java classes one to one, including Java's rounding rule Math.round(x) = ⌊x + ½⌋, so the Python predictions match the service to the day.

§2A filter that becomes an average

The Kalman variance follows a deterministic recursion that does not depend on the data. With \(M_k = P_{k-1} + q\) the prior variance,

$$P_k = \frac{M_k\,r}{M_k + r},\qquad K_k = \frac{M_k}{M_k + r}.$$
Proposition 1 · steady state

For any \(P_0 \ge 0\) the recursion converges to the positive root of \(M^2 - qM - qr = 0\), so

$$K_\infty = \frac{M_\infty}{M_\infty + r},\qquad M_\infty = \tfrac12\Big(q + \sqrt{q^2 + 4qr}\Big).$$

At \(q = 0.5,\ r = 4\) this gives \(M_\infty = 1.6861\), \(P_\infty = 1.1861\) and \(K_\infty = 0.2965\). Once \(K_k \approx K_\infty\) the update \(\hat x_k = \hat x_{k-1} + K_\infty (z_k - \hat x_{k-1})\) is exactly an exponential moving average with weight \(K_\infty\).

proofThe map \(P \mapsto (P+q)r/(P+q+r)\) is increasing and concave with derivative \(r^2/(P+q+r)^2 < 1\), so it is a contraction on \([0,\infty)\) with a unique fixed point. Setting \(P = Mr/(M+r)\) with \(M = P + q\) and clearing denominators gives the quadratic. ∎

This is a classical result. Muth showed in 1960 that exponential smoothing is the optimal forecast for exactly this local-level model[3]. What is specific to the shipped system is that it blends the filter with an EWMA whose weight, 0.3, is within 0.004 of the weight the filter converges to. After the first few cycles the blend averages two copies of the same smoother.

§3What the interval means

Under the filter's own model the predictive distribution of the next cycle is

$$z_{k+1}\mid z_{1:k} \sim \mathcal N\big(\hat x_k,\; P_k + q + r\big),\qquad P_\infty + q + r = 5.686 .$$

The service reports \(\sigma^2 = P_k + s_k^2\) instead. \(P_k\) alone is the uncertainty of the level, not of the next observation, so the observation noise \(r\) appears to be missing. My first reading was that the interval is miscalibrated by construction. That reading was wrong, and the reason is instructive.

At stationarity the EWMA variance satisfies \(\mathbb E[s^2] = (1-\alpha)\,\mathbb E[\delta^2]\), where \(\delta = z_k - m_{k-1}\) is the one-step forecast error. Because \(\alpha \approx K_\infty\), the EWMA is close to the steady-state filter and \(\mathbb E[\delta^2] \approx M_\infty + r = 5.686\). So

$$\mathbb E[\sigma^2] \approx P_\infty + (1-\alpha)(M_\infty + r) = 1.186 + 0.7 \times 5.686 = 5.166 ,$$

about 9% below the correct variance, or 5% in standard deviation. A nominal 80% Gaussian interval that is 5% too narrow covers about 78%. Rounding both endpoints to whole days and counting them as inclusive adds the rest back. The simulation agrees. On clean data the shipped interval covers 82.2% of cycles.

The interval breaks when the data stops being Gaussian. Missed logs, which merge two cycles into one, and occasional long cycles put real probability far in the tail, where a Gaussian puts almost none.

§4An absorbing gate

The outlier gate compares each observation against the EWMA moments. When it rejects an observation, nothing updates, including the moments it compares against.

Proposition 2 · lock-out

Suppose the true level shifts by \(\Delta\) and every later observation satisfies \(|z_j - m| > 3s\) for the frozen moments \((m, s)\). Then every later observation is rejected and the reported \(\mu\) never changes.

proofA rejected update leaves \((m, s, \hat x, P)\) unchanged by construction, and the feedback loop only runs on accepted updates. The gate condition at step \(j+1\) is therefore evaluated against the same \((m, s)\) as at step \(j\). By induction no observation after the shift is accepted. ∎

The condition is easy to meet. A user with regular cycles drives \(s\) down to about 1.5 to 2 days, so any lasting change of more than about five or six days, such as coming off hormonal contraception, can lock the model permanently.

§5An exact Bayesian replacement

The replacement keeps the random-walk level but stops pretending the noise is Gaussian and known. Each observation comes from a three-part mixture,

$$p(z \mid x, s) = (1-\pi_m-\pi_\ell)\,\mathcal N(z;\,x,\,s^2) \;+\; \pi_m\,\mathcal N(z;\,2x,\,2s^2) \;+\; \pi_\ell\,\mathrm{ExGauss}(z;\,x,\,s,\,\tau),$$

an ordinary cycle, a missed log that merges two cycles, and an occasional long cycle with an exponential tail (\(\pi_m = 0.05,\ \pi_\ell = 0.04,\ \tau = 10\) days). The noise scale \(s\) and the drift variance \(q\) are unknown per user and are learned jointly with the level.

Because the state is low-dimensional, the posterior can be computed exactly on a grid instead of approximated. The grid has 225 level values at 0.25-day spacing, 14 noise scales and 4 drift variances, which is 12,600 states. One filter step is four dense 225 × 225 matrix products for the drift, followed by a pointwise multiplication by the likelihood. Nothing is ever discarded, so there is no gate to lock.

The predictive distribution is integrated onto whole days. That gives an interval, a median forecast, and a proper hazard,

$$h(d) = \frac{p(T = d)}{P(T \ge d)},\qquad p(T = d \mid T > t) = \frac{p(T = d)}{P(T > t)}\ \ (d > t),$$

which is what a user mid-cycle actually wants to know. The shipped "hazard" endpoint returned a normalised Gaussian over day offsets. That is a probability mass function rather than a hazard, and it ignored the days already elapsed.

Reading the results honestly

Under contamination the robust filter wins on every proper score, and the log score gap is large because the Gaussian forecast assigns almost no probability to merged or long cycles. Its point accuracy gain is small, about 0.1 days.

Two results go against it. On clean data it over-covers, about 0.92 instead of 0.80, because it keeps paying for contamination that is not there and because equal-tailed intervals on whole days are conservative. And removing the gate without a robust likelihood, the "minimal fix", is worse than production under contamination. The gate was doing real work. The problem was only that it could never reopen.

§7A feedback loop that never saved

The hit-rate loop that retunes \(\alpha\) and the interval scale \(c\) is written correctly in isolation. The bug is in the order of persistence.

// PredictionModelService.updateOnNewPeriod(userId, start)
state = stateService.getOrCreate(userId)          // copy A loaded
autoEvaluator.evaluateOnActualStart(userId, start)
    s = modelStateService.getOrCreate(userId)     // copy B loaded
    s.params.alpha = tuned;  s.sigmaScale = tuned
    modelStateService.save(s)                     // B written
... update estimators on copy A ...
stateService.save(state)                          // A written, B's tuning overwritten

Spring Data's MongoDB save() replaces the whole document, so the stale copy wins every time and the tuned values are lost. The port reproduces both behaviours. As written, coverage under contamination is 0.749. Had the loop persisted, it would have been 0.763. This finding comes from reading the code and simulating it, not from observing the running service.

§8Ranges with a guarantee

The production range promised 80% and delivered 74.7% under contamination. A range should keep its promise by construction, whatever the model gets wrong.

Split conformal prediction does this for any forecaster[11]. Measure how badly each forecast missed with a score, here the production error in units of its own spread, \(s = |y - \hat\mu| / \hat\sigma\). Compute that score for \(n\) calibration users at a given cycle. For a new user at the same cycle, report \(\hat\mu \pm \hat q\,\hat\sigma\), where \(\hat q\) is the \(\lceil (n+1)(1-\alpha) \rceil\)-th smallest calibration score.

Proposition 3 · split conformal coverage

If the calibration users and the new user are exchangeable, the new user's cycle falls in the range with probability at least \(1 - \alpha\), for any forecaster and any \(n\).

proofThe forecaster is fixed before the calibration users are seen, so the \(n+1\) scores are exchangeable and the new score is equally likely to take any rank among them. Ties only help. The cycle is covered exactly when the new score is at most \(\hat q\), which happens when its rank is at most \(\lceil (n+1)(1-\alpha) \rceil\). That has probability at least \(\lceil (n+1)(1-\alpha) \rceil / (n+1) \ge 1 - \alpha\). ∎

The calibration uses one forecast per user at each cycle index. So the argument needs users to be exchangeable with each other, which a random sample of users is, and never needs the cycles of one user to be exchangeable over time, which they are not. I simulated 4,000 new users from the contaminated cohort and split them into calibration and test halves 200 times at random.

§9Limitations and next steps

Every number here depends on a synthetic generator whose parameters are my assumptions, not literature estimates. The direction of the findings in §2, §3, §4 and §7 does not depend on them, since those follow from the algebra or the code. Their size does.

The robust model's contamination rates are fixed. Learning them, together with the noise prior, by empirical Bayes across users should remove the clean-data over-coverage. That is the next step, followed by validation on a licensed public cycle dataset. The conformal ranges of §8 would carry over unchanged, recalibrated on the real users.
